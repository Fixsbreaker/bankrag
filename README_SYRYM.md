# BankRAG Оценка поиска и первые измерения

Подготовлено 29 октября 2026 года в локальной ветке `syrym/evaluation` от `654d97a`. В GitHub изменения не отправлены. В архиве находятся полный исходный код текущей локальной копии и результаты; оригинальные PDF, модели, виртуальное окружение и построенный индекс исключены.

## Что готово

- Скрипты скачивания документов, оценки поиска и сравнения четырёх индексов.
- Три официальных PDF Halyk и Kaspi: 67 страниц, 710 фрагментов при pypdf 6.21.4. URL и SHA-256 находятся в `data/sources.json`.
- Набор разработки: 20 вопросов с проверенной страницей и фразой-ответом, 5 персональных вопросов без ответа в публичных тарифах. В `eval/questions.jsonl` есть ориентиры для ручной проверки ответов.
- Варианты оценки: векторный поиск, простой TF-IDF и гибридный поиск с явным ограничением по банку или названию документа и объединением рангов RRF.
- В PDF-фрагментах сохраняются страницы. Интерфейс показывает ссылку на PDF банка и страницу, если они доступны в индексе.

## Запуск

Требуется Python 3.12. Команды выполняются из каталога проекта.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python scripts/download_docs.py
python scripts/build_index.py --raw data/raw/official --out index --kind hnsw
python scripts/eval_retrieval.py
python scripts/eval_retrieval.py --method hybrid --reuse-queries --out results/retrieval_hybrid.json
python scripts/eval_keyword.py
python scripts/benchmark.py --repeats 30
python -m unittest discover tests -v
```

Эмбеддинги `intfloat/multilingual-e5-small` скачиваются при первом запуске; LLM и платный API для этих команд не нужны. В текущем прогоне использована ревизия модели `614241f622f53c4eeff9890bdc4f31cfecc418b3`. Первый скрипт оценки рассчитывает эмбеддинги вопросов отдельным процессом, чтобы избежать конфликта OpenMP между PyTorch и FAISS на macOS. Повторное использование эмбеддингов проверяет хеш вопросов и имя модели.

`download_docs.py` остановится, если банк заменит PDF по тому же URL: сначала нужно перепроверить версию и разметку. При изменении корпуса пересоберите индекс и повторите оценку. Для воспроизведения установленных версий есть `requirements-eval-lock.txt`; это снимок проверенного окружения macOS ARM, без пакетов необязательного интерфейса и LLM.

## Первые результаты

| Поиск | Нужный фрагмент в топ-5 | MRR@5 |
| --- | --- | --- |
| Векторный HNSW | 8 из 20, 40% | 0,2242 |
| TF-IDF | 11 из 20, 55% | 0,4517 |
| Гибридный с выбором банка или документа | 14 из 20, 70% | 0,4017 |

Гибридный поиск улучшает попадание в топ-5, но уступает TF-IDF по MRR. Это разные свойства выдачи. Гибрид разработан после просмотра результатов на этом же наборе: результат служит проверкой разработки, а не независимой оценкой точности. Пять вопросов без ответа исключены из знаменателя Hit/MRR; отказ LLM здесь не проверялся.

| Индекс | Размер полного файла индекса, МБ | Медиана запроса, мс | ANN Recall@5 относительно Flat |
| --- | --- | --- | --- |
| Flat | 1,091 | 0,0213 | 100% |
| HNSW | 1,283 | 0,0378 | 100% |
| HNSW+SQ8 | 0,468 | 0,0550 | 98,4% |
| IVF-PQ | 0,438 | 0,0217 | 46,4% |

Условия: 710 нормализованных векторов размерности 384, те же 25 запросов для всех индексов, один поток FAISS, 2 прогрева, 30 повторов каждого запроса в перемешанном порядке; HNSW M=32 и efSearch=64, PQ m=16. Аппаратная конфигурация и точные значения записаны в `results/benchmark.meta.json` и `results/benchmark.csv`. Сравнение относится к чистому векторному поиску; гибридный поиск в этот замер задержки не входит.

Измерен размер сериализованного индекса, а не пик оперативной памяти. Время не включает эмбеддинг, генерацию ответа или дисковый ввод-вывод. На таком небольшом корпусе Flat оказался быстрее HNSW; ускорение на больших данных этим экспериментом не установлено. У IVF-PQ недостаточно обучающих примеров: FAISS рекомендует минимум 9984 для 256 центроидов, в корпусе 710. Его результат предварительный. Эти четыре конфигурации не являются сравнением SQ и PQ при равной памяти.

## Что согласовать с командой

Альнур: выбрать окончательный корпус и версии документов. У скачанных файлов не установлена актуальность тарифов на сегодняшний день; это снимки документов для эксперимента. Перепроверить извлечение таблиц и добавить контекст названия банка и раздела: сейчас разбиение может отделять тариф от его условий. Замена PDF меняет фрагменты и требует повторной оценки.

Диас: интерфейс уже читает `results/benchmark.csv`; теперь в нём есть измеренные данные, `recall_at_5`, полный размер индекса и отдельный размер кода вектора. Согласовать подписи и единицы. Текущий чат использует прежний векторный `search()`. Гибрид доступен отдельно как `search_hybrid()` и в скрипте оценки; его оценка RRF не является косинусной близостью. До подключения гибридного режима к LLM нужно отключить или заменить косинусный `MIN_SCORE` для этого режима. Проверку реальных ответов, ссылок и отказов выполнять отдельно.

Сырым: расширить вопросы, добавить банковские вопросы без ответа, независимую тестовую выборку и более крупный корпус. Текущие вопросы разработки преимущественно относятся к одному документу Homebank, поэтому ещё не представляют весь набор банковских сценариев.

Исходный код оценки, размеченные вопросы, таблицу результатов, пример найденного фрагмента с исходным PDF и страницей, а также конкретный найденный недостаток: одинаковые тарифные строки разных документов требуют контекста и выбора источника.
