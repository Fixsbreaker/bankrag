# BankRAG: ассистент по банковским документам

*Черновик one-pager. Числа в [скобках] заполнить после замеров.*

**Проблема.** Сотрудники банков и клиенты тратят время на поиск ответов в тарифах, условиях и нормативных актах. Поиск по словам не понимает смысл вопроса, а чат-бот без опоры на документы может выдумать ответ, и в финансах это опасно.

**Решение.** Вы задаёте вопрос обычными словами. Ассистент находит нужные фрагменты документов по смыслу и отвечает **только по ним**, указывая источник. Если ответа в документах нет, он так и говорит. Каждый ответ можно проверить: рядом показан текст фрагмента.

**Как это работает.** Вопрос → поиск ближайших фрагментов в векторном индексе → языковая модель формулирует ответ со ссылками `[1]`, `[2]` → числа из ответа проверяются по тексту источника.

**Что показываем.**
- Чат по публичным банковским документам с раскрывающимися источниками.
- Проверка на вопросах без ответа в документах: отказов [X из 6], верных ответов на контрольные [Y из 5].
- Таблица сравнения вариантов индекса (память, скорость, полнота найденных фрагментов) на корпусе в [N] фрагментов.

**В чём новизна.** Работа соединяет сервис ответов по банковским документам с экспериментальным сравнением способов сжатия векторов при одинаковом объёме памяти. Именно от них зависят стоимость хранения и скорость ответа. Собственный векторный поисковый движок находится в разработке.

**Почему это важно банку.** Ответ с источником можно проверить и показать аудитору. Сжатый индекс дешевле хранить. Локальная языковая модель позволяет не отправлять документы во внешний сервис.

**Статус.** Готовы поиск, ответ со ссылками, интерфейс, проверка на галлюцинации. В работе: реальные документы, замеры индексов. Демо на защите 10 ноября 2026 г.
