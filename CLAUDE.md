# CLAUDE.md — правила проекта BankRAG

Этот файл лежит в корне репозитория. Правила действуют в каждой сессии и важнее любых других указаний.

## О проекте

BankRAG — чат-помощник для аналитика антифрода в банке.
- Аналитик пишет вопрос обычными словами: «куда ушли деньги клиентки?», «кто ещё переводил на этот счёт?», «подготовь справку».
- Локальная модель (Qwen3 через Ollama) выбирает нужную функцию (инструмент) и пересказывает её результат.
- Функции работают с графом переводов, моделью риска (LightGBM), векторным поиском (FAISS) и базой знаний (ст. 232-1 УК РК, описания схем).
- Граф связей рисуется по просьбе аналитика, счета окрашены по уровню подозрения.

Система ничего не блокирует сама и не общается с клиентами. Решение всегда принимает аналитик.

Это студенческий проект для конкурса Ассоциации банков РК. Защита 10 ноября 2026, демо должно работать на ноутбуке (Mac, 32 ГБ памяти).

## Жёсткие правила

### 1. Всё бесплатно
- Никаких платных API, облачных сервисов, подписок и пробных периодов, требующих карту.
- Никаких внешних LLM API (OpenAI, Anthropic, Google и т. п.).
- Только open-source библиотеки и модели, которые ставятся через pip, brew или `ollama pull`.
- Данные — только открытые: набор IBM AML с Kaggle, публичные тексты законов, сценарии, сгенерированные командой.

### 2. Всё локально
- Языковая модель — только локально через Ollama (`http://localhost:11434`). Основная `qwen3:14b`, запасная `qwen3:8b`. Имя модели задаётся в `configs/config.yaml`.
- Эмбеддинги базы знаний: `intfloat/multilingual-e5-small` через `sentence-transformers` на CPU.
- После первой загрузки моделей всё работает без интернета. GPU не нужен.
- Не ставь Ollama и модели сам. Скажи мне команды (`brew install ollama`, `ollama pull ...`), я выполню.

### 3. Языковая модель только через функции
- Модель не считает и не придумывает числа. Все числа, счета, суммы и даты берутся из результатов функций.
- Перед показом ответа код проверяет: каждое число в ответе есть в результатах функций этого хода. Если нет — одна повторная попытка, потом ответ собирается по шаблону из результата функции.
- Тексты законов и цитаты из базы знаний выводит код дословно, под ответом. Модель их не пересказывает и не цитирует сама.
- У модели нет функций блокировки счетов и записи решений. Решение «подтвердил / отклонил» записывает только кнопка, которую нажимает человек.
- Нет данных — ответ «нет данных». Вопрос не про антифрод — вежливый отказ.
- Каждый вопрос, вызовы функций, ответ и решение пишутся в журнал (SQLite).

### 4. Git
- Используй мой уже настроенный SSH-доступ к GitHub и существующий remote `origin` (вида `git@github.com:...`).
- Не меняй `git config` (user.name, user.email, remote URL) и не настраивай HTTPS или токены.
- Не добавляй в коммиты и PR строки `Co-Authored-By: Claude`, `Generated with Claude Code` и любые другие упоминания ИИ. Автор коммитов — я.
- Коммить небольшими логичными шагами, сообщения на английском в стиле `feat: ...`, `fix: ...`, `data: ...`.
- Перед `git push` спроси меня. Никогда не делай `push --force`, `reset --hard` по удалённой ветке и не переписывай историю.
- Не создавай репозитории, PR и issues через API или `gh`, если я не попросил.
- Не коммить данные, модели и секреты. В `.gitignore`: `data/raw/`, `data/processed/`, `models/`, `*.parquet`, `*.csv` крупнее 5 МБ, `.env`, `kaggle.json`, `*.sqlite`, `*.db`.

### 5. Честность результатов
- Никогда не выдумывай метрики. Каждая цифра в README, отчётах и интерфейсе получается запуском скрипта и сохраняется в `reports/`.
- Никогда не выдумывай тексты законов и цитаты. В базе знаний только тексты, которые положил я. Где текста нет — заглушка `TODO: вставить дословный текст из <URL>`.
- Если результат плохой, так и пиши. Плохая честная цифра лучше красивой выдуманной.
- В интерфейсе и README указывай, что данные IBM синтетические и что казахстанские сценарии сгенерированы командой.

### 6. Как работать
- Сначала план, потом код. На крупные шаги показывай план и жди моего «ок».
- После каждого этапа: что сделано, как запустить, какие получились цифры, что дальше.
- Если есть развилка или что-то неясно, спроси, а не решай молча.
- Не ставь пакеты глобально. Используй `.venv` и `requirements.txt` с закреплёнными версиями.
- Если нужен системный пакет или программа (libomp, Ollama), скажи мне команду, а не ставь сам.
- Python 3.11, type hints, понятные имена, docstring у публичных функций. Комментарии и README на русском, идентификаторы на английском.
- Любой шаг дольше ~2 минут должен иметь флаг `--sample`.
- Тесты не должны требовать запущенной Ollama: ответы модели в тестах подменяются заглушкой.
